# Архитектура в YAML

Источник архитектуры — `docs/architecture/`. `ARCHITECTURE-SPINE.md` собирается из него и руками не правится.

Команды запускаются из корня проекта. `<spine>` — файл `_bmad-output/planning-artifacts/architecture/*/ARCHITECTURE-SPINE.md`.

| Когда | Команда |
| --- | --- |
| Spine создан впервые | `uv run .doc-kit/doc-architecture/tools/arch.py split <spine> --out docs/architecture` |
| Посмотреть единицу | `uv run .doc-kit/doc-architecture/tools/arch.py unit docs/architecture AD-5` |
| Архитектура для требований | `uv run .doc-kit/doc-architecture/tools/arch.py pack docs/architecture --reqs FR-1,FR-2` |
| После правки YAML | `build docs/architecture --spine <spine>`, затем `check docs/architecture --spine <spine>` |

| Что затронет отказ объекта | `uv run .doc-kit/doc-architecture/tools/arch.py impact docs/architecture I-webhook` |

## Модель системы

Spine фиксирует решения. Модель описывает само устройство системы, её заполняют сразу после первого Spine по PRD и Spine. Каждый объект лежит в своём файле, схема находится в `.doc-kit/doc-architecture/schemas/`.

| Порядок | Объект | Папка | Откуда берётся |
| --- | --- | --- | --- |
| 1 | Участник | `actors/` | Роли Глоссария и внешние организации |
| 2 | Система | `systems/` | Своя система и всё внешнее, с чем она связана |
| 3 | Объект данных | `data/` | Термины Глоссария, у которых есть состояние или срок жизни |
| 4 | Функция | `functions/` | Требования PRD: что система делает, что читает и пишет |
| 5 | Процесс | `processes/` | Пути пользователя PRD, разбитые на шаги с входом и выходом |
| 6 | Сервис | `services/` | Что получает потребитель. Обязательство ссылается на сценарий `quality.yaml` |
| 7 | Компонент и узел | `components/`, `nodes/` | Контейнеры и развёртывание из Spine |
| 8 | Хранилище | `stores/` | Где лежат объекты данных |
| 9 | Интеграция | `integrations/` | Канал: протокол, вход, таймаут, повтор, идемпотентность |
| 10 | Поток данных | `flows/` | Что движется по каналу, зачем и по какому событию |

- Объект заводится, только если его изменение или отказ влияет на сервис. Лишнее не описывается.
- У каждого объекта есть `owner`, `lifecycle` и `criticality`.
- Поток говорит, что движется и зачем. Интеграция говорит, по какому каналу.
- Функция говорит, что система умеет. Сервис говорит, что и на каких условиях получает потребитель.
- Объект данных логический, хранилище физическое. Один объект может лежать в нескольких хранилищах.
- Поток между разными системами всегда указывает интеграцию в поле `over`.
- Вход шага процесса появляется во входе процесса или в выходе предыдущего шага.
- Значения типов берутся из `types.yaml`, шаблон лежит в `.doc-kit/doc-architecture/templates/types.yaml`.
- Неизвестное не придумывается: нет решения, значит открытый вопрос.

Связи проверяет `check.py` из `doc-gates`.

## Правила

- Читайте единицу или пакет, а не весь Spine.
- Новое решение — новый файл `decisions/AD-n.yaml` и строка в `decisions/_order.yaml`. Номера не переиспользуются.
- Блоки, параметры и FMEA описываются по схемам из `.doc-kit/doc-architecture/schemas/`.
- Новый блок: скопируйте `.doc-kit/doc-architecture/templates/block.yaml` в `blocks/<компонент>/<блок>.yaml`. Заполненность и ссылки карточки считает `check.py` из `doc-gates`.
- Если `check` сообщает о ручной правке Spine, перенесите её в YAML и выполните `build`.
